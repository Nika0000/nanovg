---
title: Adding or changing an API
description: Update NanoVG's public header, implementation, tests, live examples, and documentation together.
---

Public drawing APIs begin in `include/nanovg/nanovg.h` and are implemented by `src/nanovg.c`. A change is complete when callers, backends, bindings, tests, and docs agree on its behavior.

## Checklist

<Steps>
<Step>

### Update the public API

Add or update declarations and comments in `nanovg.h`.

</Step>
<Step>

### Implement the behavior

Implement portable behavior in `src/nanovg.c` or the relevant backend.

</Step>
<Step>

### Add focused tests

Cover validation, state, ownership, and failure behavior.

</Step>
<Step>

### Check renderer integration

Review every renderer callback or structure affected by the change.

</Step>
<Step>

### Stage the live-preview sources

Run `npm run build` in `docs/site` to stage the updated public header and implementation.

</Step>
<Step>

### Update the example

Update or add a live example when the change is user-facing.

</Step>
<Step>

### Update the documentation

Update the relevant guide and API-reference page.

</Step>
<Step>

### Run the checks

Run core tests, affected examples, and docs checks.

</Step>
</Steps>

Avoid silently changing structure layouts, enum values, ownership rules, or accepted ranges. Record unavoidable compatibility changes in [Changelog and compatibility](/compatibility).
